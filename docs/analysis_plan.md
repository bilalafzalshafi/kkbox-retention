# Analysis plan · implemented real-data run

Can recent listening improve an actionable monthly churn forecast beyond billing history? The decision is whether listening signals justify inclusion in a risk model used to recruit an audience for a randomized retention experiment. This is a prediction study; it cannot estimate the effect of contacting customers.

## Population and clock

The snapshot is 00:00 on the first calendar day of each month, in the dataset's date convention. Since no intraday timestamps are available, every predictor event must have date strictly before the snapshot. Transaction rows dated on the first day of the month can contribute to outcomes, never to that day's predictors. The latest officially ordered pre-snapshot billing state must show a positive-duration subscription whose scheduled expiry is on or after the snapshot and before next month. A cancellation flag does not by itself make a still-entitled subscriber inactive. An account with an already expired subscription is outside this target population, even if it later reactivates.

Eligibility and the scheduled expiry used for snapshot inclusion are frozen at the snapshot. We do not select users because a subsequent transaction shows them expiring, and we never overwrite the eligibility expiry with a future expiry. This avoids conditioning the audience on the outcome. The outcome calculation has a separate adjusted-expiry clock: after the snapshot, cancellation records can shorten the expiry used to measure the renewal gap before the first later non-cancellation transaction.

## Outcome

A renewal is the first non-cancellation transaction on or after the snapshot whose gap from the current adjusted expiry is less than 30 days. The adjusted expiry starts as the frozen scheduled expiry from snapshot eligibility, then intervening cancellation records can shorten it before the first later non-cancellation, matching the supplied reference labeller's renewal-gap routine. Zero-price extensions can qualify; this endpoint measures subscription continuation, not paid revenue. Early renewals before the original expiry count because their gap is negative. A later cancellation does not undo the historical fact of an otherwise qualifying renewal; sustained paid retention is a separate experimental secondary outcome.

Churn is the absence of a qualifying renewal through the last valid renewal day. A renewal gap of 29 days counts; a gap of 30 days is churn. This monthly business population uses all prior history rather than the competition script's January-only candidate construction, so it is not a Kaggle leaderboard reproduction. We do not reuse train.csv labels for different snapshot dates.

The supplied transaction coverage must extend through the entire deadline for every labeled example, including renewers. Otherwise the label stays null. Complete follow-up is required for positives and negatives alike. Multiple transaction rows on the same day are ordered with the official labeller's deterministic rule: transaction date, then descending concatenated plan-list-price, plan-days and payment-method signature, then renewal/cancellation and expiry tie-breaks. Exact duplicate projected records are removed.

## SQL feature contract

The unit of analysis is one (subscriber, snapshot) pair. Raw identifiers are join keys, never model features. Billing includes plan duration, list price, amount paid, auto-renew and cancellation status, payment method, days until scheduled expiry, days since the last transaction, and time since the first observed transaction. The last quantity is observed tenure, a lower bound on lifetime tenure, because the transaction history is left-truncated. Member demographics and registration metadata are not needed for this analysis.

Listening uses the half-open window [snapshot minus 28 days, snapshot). Activity is a date with strictly positive listening seconds. Compute active days, summed seconds, days since the most recent positive activity, and recent-14-day minus previous-14-day seconds. Keep the raw differences for SQL inspection; the models use log(1+seconds) and the difference in log(1+seconds) between the two fortnight windows. For subscribers with no observed positive listening, recency is censored at the beginning of the supplied log history and an explicit censoring indicator is included. Missing user-day records mean zero activity only under declared complete source coverage; an absent or partial extract is not evidence of inactivity.

Negative or nonfinite listening values are dropped with counts recorded; the real files contain a small number of sentinel-like negative totals before the modeled snapshot windows. Daily totals above 86,400 seconds are capped at that bound, with counts recorded. This is a prespecified measurement-cleaning choice; a real-data run with material capping requires sensitivity analysis before interpreting behavioral effects. Distinct conflicting totals for the same user and day fail validation. Duplicate copies of identical projected user-day values are removed.

## Time split and model selection

Default snapshots run April 2016–March 2017. October 2016 is validation. January and February 2017 are untouched test origins; March is an example of prospective scoring with incomplete labels. Every historical cohort is withheld from fitting until the latest in-month expiry plus a 29-day valid renewal window has closed. Thus the latest possible label in that cohort has become observable. An October cohort becomes available November 30; a January 2017 cohort becomes available March 2. A January model cannot learn December outcomes, and a February model cannot learn January outcomes.

At every validation and test origin, refit on all earlier, fully mature cohorts. Subscribers may recur between periods: this estimates future risk for an installed subscriber base. No subscriber ID or past target label enters the feature set. Export the repeat-subscriber fraction. A separate new-user generalization claim would need a different split.

Compare historical training prevalence, billing logistic regression, billing plus listening logistic regression, billing XGBoost, and billing plus listening XGBoost. Logistic regularization C is chosen from 0.1 and 1; tree depth from 2 and 4. All other settings are fixed in code. Fit encoding, imputation and scaling inside each training split. No class balancing or outcome oversampling is used, preserving the prevalence target for probability estimation. Select each model's hyperparameter by validation log loss. Choose the potential deployment model using validation only, before viewing test results. No test-period recalibration or threshold tuning is performed. If probabilities later need recalibration, reserve a distinct mature calibration period and repeat the backtest.

## Metrics and uncertainty

Primary comparison is the paired out-of-time log-loss change from adding listening within the same model family. Report log loss and Brier score for all models, fixed-bin reliability curves with counts, descriptive expected calibration error, and the fraction of eventual churners captured in the highest-risk 10% each month. Capacity is ceil(0.10 × evaluable cohort size), with deterministic SHA-256 identifier tie-breaking; show the exact selected count and fraction. Pooled recall sums monthly captured churners and divides by all churners across those months. The same person can appear in more than one month. Report auto-renew and manual-renew segments separately as diagnostics.

The main bootstrap resamples subscriber IDs with all their test-month observations together, comparing fixed paired predictions. Its percentile interval quantifies sampling uncertainty conditional on fitted models and these calendar months, not training variability or temporal drift. Avoid treating a two-month backtest as proof of stable future improvement. Feature importance is deliberately not used as evidence of causality.

Cohort renewal rates are renewers divided by labeled snapshots, with eligible, labeled, unknown and censored counts reported separately. Same-day transaction rows are resolved by the official deterministic ordering rather than excluded as ambiguous. The live top-decile audience is scored from all feature-eligible subscribers, without filtering on future label availability.

## Data access and scale

The original and v2 transaction and listening CSVs came from the authenticated KKBOX competition source and remain local under `data/raw/`. Coverage was inspected before setting `coverage_confirmed=true`: the combined transaction and listening sources support the configured snapshots and follow-up through 2017-03-31. Maximum row dates alone do not establish absence of missing days or missing files; the recorded run also audits row counts, invalid listening rows, capped listening rows and same-day transaction ordering counts.

Default real runs use md5_number_lower(msno) modulo 100 equals 0: approximately 1% of subscribers with their full history, independent of outcomes. DuckDB filters while reading, though it still scans the raw CSVs. This is a laptop-oriented first analysis. Results must state the sampling fraction. Increase to modulus 10 or 1 only when memory and disk permit. Data staging is disk-backed; the sampled feature matrix and training data are in memory. First convert/distribute sources to Parquet and redesign chunking before claiming production scale. Source file sizes, optional hashes, software versions, exclusions and exact configuration accompany every deliverable.
